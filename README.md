# Векторный конструктор изометрических иллюстраций

Веб-сервис на Python (Django 5 и Django REST Framework), собирающий векторные изометрические сцены из готовых библиотечных SVG-компонентов. 

Главное архитектурное требование проекта — полный отказ от диффузионных нейросетей и растрирования. Итоговая сцена не генерируется «с нуля пикселями», а выстраивается исключительно из оригинальных векторных объектов Figma. В результате файл сохраняет масштабируемость, исходные контуры и чистую структуру слоев, оставаясь пригодным для прямого открытия и редактирования в графических редакторах.

---

## Быстрый запуск

Управление проектом и зависимостями изолировано через `uv` (требуется Python 3.12+):

```bash
cd Job_Task_3

# Запуск локального сервера (виртуальное окружение развернется автоматически)
uv run python main.py
```

Интерфейс откроется по адресу **http://127.0.0.1:8001/**.

### Прогон тестов:
```bash
uv run pytest
```
Набор из 17 модульных тестов проверяет парсинг всех 40 векторных ассетов, корректность изометрических слоев, инвариантность пропорций Figma 1:1, математику трех вариантов компоновки, правила цветовой изоляции и контракты REST API.

## Архитектура и технические решения

### 1. Хранение компонентов и изоляция пространств имен в DOM (`assets/`)

В основе сервиса лежит каталог из 10 предметов (`book`, `phone`, `headphones`, `lamp`, `wallet`, `puzzle`, `coin`, `folder`, `pen`, `vase`). Каждый предмет отрисован в четырех вариациях — итого 40 чистых векторных файлов:
* по детализации: `L` (для крупных планов) и `S` (упрощенная геометрия для компактных баннеров);
* по визуальной роли: `Main` (полноцветная изометрия переднего плана) и `Bg` (монохромный силуэт для создания ощущения глубины сцены).

Метаданные (исходные габариты viewBox, пропорции и поисковые теги) вынесены в `assets/library.json`. Правила базовых цветовых схем собраны в `assets/palettes.json`.

При сборке нескольких SVG в один документ возникает скрытая проблема: коллизии идентификаторов. Если дважды вставить на холст лампу, браузер встретит повторяющиеся теги `<clipPath id="clip0">` и перепутает маски обрезки. Чтобы этого избежать, `LibraryService` отсекает внешние теги `<svg>`, а `SvgBuilder` на лету навешивает префиксы на внутренние блоки `<defs>` (`o0_clip0`, `o1_clip0`). Каждый добавленный на холст предмет живет в собственном изолированном пространстве имен.

### 2. Изометрическая слотовая модель (`LayoutEngine`)

Попытка доверить расстановку координат языковой модели или наивному генератору случайных чисел быстро показала свою несостоятельность: объекты либо разлетались по краям холста, либо сбивались в бесформенную кучу. 

Вместо этого мы применили точные пространственные замеры эталонных макетов Figma (`drop_clustered_l.svg`, `drop_headline_l.svg`, `drop_offset_l.svg`). Движок раскладывает сцену по трем функциональным зонам:
1. **Базовое плато (левый фланг):** плоский крупный предмет (`book` или `folder`), лежащий на столе. На его поверхность с гарантированным подъемом по слоям ложатся смартфон или блокнот.
2. **Связующий мост (центр):** средний объект вроде наушников или кошелька, перекрывающий край книги и связывающий композицию воедино.
3. **Контрбаланс (правый фланг):** вертикальный акцент на заднем плане (лампа или ваза) плюс компактный горизонтальный аксессуар впереди (ручка или монета).

Физика привязки опирается на нижнюю точку касания пола — **Bottom-Center Ground Plane**:
$$gx = rx \cdot cw, \quad gy = ry \cdot ch, \quad x = gx - \frac{w}{2}, \quad y = gy - h$$
Высокие предметы не проваливаются сквозь стол, а плоские блокноты не повисают в воздухе.

Глубина сцены ($Z$-index) рассчитывается динамически. Чем ниже подошва объекта на экране, тем ближе он к зрителю. Для предметов, лежащих непосредственно на книге, выставляется флаг `on_surface`, принудительно выносящий их на передний план (+1000 к базовому уровню). Независимо от того, сколько объектов выбрано — два, три или шесть, итоговый прямоугольник сцены автоматически центрируется по холсту.

Поддерживаются три сценария раскладки:
* `clustered`: сбалансированный остров в центре композиции;
* `under_headline`: компактная группировка справа, освобождающая левую половину под заголовок и акцидентный текст;
* `offset`: динамический каскад по диагонали 30 градусов.

### 3. Ролевая перекраска и проверка палитр (`PaletteService`)

В системе заложено жесткое правило дизайн-системы:
> Цвета фона разрешено применять внутри объектов. Цвета объектов категорически запрещено использовать в качестве фоновых заливок.

При импорте пользовательской палитры сервис проверяет пересечение множеств оттенков. Если найдено совпадение, запрос немедленно отклоняется с кодом `400 Bad Request`.

Сама перекраска выполняется на уровне векторного синтаксиса через регулярные выражения. Алгоритм находит заливки и обводки, сопоставляет их с картой текущей палитры и подставляет новые HEX-значения. При этом системный черный цвет контура (`#181817`) и белые блики (`#FFFFFF`) остаются нетронутыми.

### 4. Разбор метафор и сценарии работы (`NlpMetaphorAgent`)

Сервис рассчитан на два практических сценария:

* **Сценарий 1 (Семантический подбор):** пользователь пишет тему или заголовок (например, *«Дистанционное обучение и лекции»* или *«Семейный бюджет»*). Анализатор определяет контекст, отбирает от 3 до 5 релевантных предметов, распределяет роли (доминанты `Main` и фоновые силуэты `Bg`) и подбирает раскладку. По умолчанию используется внешний вызов Gemini Flash со структурированным JSON-ответом. Если же API-ключ отсутствует или сеть недоступна, управление бесшовно перехватывает встроенный локальный анализатор, работающий по семантическому графу ключевых слов и онтологии библиотеки. Сцена формируется быстрее чем за 150 миллисекунд.
* **Сценарий 2 (Ручной конструктор):** оператор сам выбирает нужные компоненты из каталога, назначает их роль и формат. В интерактивном окне доступно свободное перемещение элементов (Drag & Drop), переключение порядка перекрытия («Вперед» / «Назад»), удаление, дублирование и смена цветовой гаммы в один клик.

Готовый результат отдается кнопкой «Скачать SVG» в виде валидного монолитного векторного файла.

## Использованные AI-инструменты

1. **Google Gemini Flash / DeepMind Reasoning**: проектирование архитектуры сервиса, анализ исходных SVG-файлов из Figma, расчет матриц изометрических коэффициентов и верификация формул компоновки.
2. **Семантический модуль `NlpMetaphorAgent`**: гибридный анализатор текста, связывающий абстрактные метафоры пользователя с предметными категориями графической библиотеки.

## Примеры готовых композиций (`examples/`)

В репозиторий включены три демонстрационных SVG-файла, демонстрирующие возможности движка на разных форматах:

1. `examples/example_1_education_purple_1200x630.svg` — горизонтальный баннер 1200×630 на тему дистанционного образования. Лейаут *Под заголовок*, фиолетовая палитра, детальные ассеты `L`. Свободная зона слева оставлена под текст.
2. `examples/example_2_finance_peach_1000x1000.svg` — квадратный формат 1000×1000 на тему личных финансов. Центральная компоновка *Собранно*, персиковая гамма, плотная группа с кошельком, монетой и телефоном.
3. `examples/example_3_team_mint_800x1200.svg` — вертикальный постер 800×1200 про командную работу. Диагональный каскад *Со смещением*, мятная гамма, компактные элементы размера `S`.

## Структура кодовой базы

```
Job_Task_3/
├── assets/                    # Исходные графические материалы
│   ├── elements/              # 40 векторных ассетов (10 объектов × L/S × Main/Bg)
│   ├── backgrounds/           # Изометрические фоновые сетки
│   ├── templates/             # Эталонные SVG-макеты из Figma
│   ├── library.json           # Каталог объектов, теги и размеры viewBox
│   └── palettes.json          # Описание цветовых схем и правил заливок
├── composer/                  # Приложение конструктора (Django)
│   ├── models.py              # Модели сохраненных композиций и кастомных палитр
│   ├── serializers.py         # Валидаторы DRF
│   ├── views.py               # REST API контроллеры
│   ├── tests.py               # 17 модульных тестов
│   ├── static/                # Стили холста и клиентский скрипт Drag & Drop
│   └── services/              # Изолированные сервисы бизнес-логики
│       ├── library_service.py # Загрузка, нормализация и кеширование SVG
│       ├── layout_engine.py   # 3-зонная слотовая модель и физика Z-Index
│       ├── palette_service.py # Ролевая перекраска и проверка ограничений цвета
│       ├── svg_builder.py     # Сборка итогового SVG-документа
│       └── nlp_agent.py       # Двухконтурный семантический анализатор метафор
├── examples/                  # 3 эталонных сгенерированных SVG-файла
├── config/                    # Настройки проекта Django
├── main.py                    # Быстрый запуск сервиса
├── pyproject.toml             # Декларация зависимостей для uv
└── README.md                  # Архитектурное описание проекта
```
